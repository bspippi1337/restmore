FIG. 00 / TERRAIN STUDY
01 / THE IDEA

An API is a territory.
The documentation is the map.
Evidence is the compass.

RESTMORE is not an endpoint fuzzer. It shows what a source documents and where that claim originated. Its optional, bounded GET verification requires human GitHub review and explicit per-host authorization.

02 / FOUR INSTRUMENTS

From source
to understanding.

Deliberately simple stages. Defined scope. Traceable operations. Reusable outputs.

ACQUISITION DESK

Begin with permission.

Preview scope or authorize bounded HTTPS documentation retrieval; import local OpenAPI JSON instead.

OPERATION ATLAS

See the documented.

Navigate methods and routes on an orbital map or an exact route list.

SOURCE INTELLIGENCE

Inspect the claim.

Source URL, operation identifier, summary and SHA-256 provenance close to each route.

Evidence, with a way out.

Export library records, supported OpenAPI and Postman formats, Mermaid diagrams and SVG plates. Copy a request template without running it.

TRUTH IN THE PRODUCT: No operation execution, no guessed paths, and no claim that documentation equals complete live-system coverage.
03 / NATIVE BY DESIGN

04 / VERIFICATION MODE

Evidence meets
the response.

GitHub review first. A manual Authorize click second. The selected OpenAPI atlas must match the domain.

No guessing. No fuzzing.

Only up to five literal documented GETs with explicit 200/204 response contracts may be checked. RESTMORE compares expected and observed status, content type and basic JSON shape. Full schema validation is not claimed.

HUMAN-IN-THE-LOOP: A GitHub repository search result is not proof of domain ownership or permission.
